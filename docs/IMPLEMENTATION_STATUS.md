# 实现与验证记录

**EEGqc 0.2.0 · 2026-10-30**

本轮补齐了组合条件、显示滤波、连续时间段 QC、ICLabel、ASR，以及 EpochLabel 贡献和研究基线链路。已有 M0/M1 核心、主要 M2 能力及 M4 采集工具；真实用户完整流程与性能验收、M5 模型研究仍未完成。后续按[下一阶段详细计划](DEVELOPMENT_V0_3.md)推进，功能不要求与 ManualQC 完全对齐。截图来自实际 Qt 应用，演示数据明确标为合成。

## 已实现

| 范围 | 当前能力 |
|---|---|
| 数据与内核 | EEGPrep .set 读取/导出，内部 V 单位、epoch × channel × sample；输入只读；来源与 TrialID 映射 |
| 实时处理 | 全秩/降秩/部分通道 ICA 保留成分重建、EEGPrep 球面插值、删除通道、平均参考；预览与导出共用内核 |
| ERP | 增量均值，删除/恢复 epoch，多字段 AND/OR、数值/集合条件，命名叠加，基线及处理/拒绝/整体对比 |
| 显示与属性 | 全记录/完整 epoch 的 FIR 显示滤波、固定窗口一致性；通道 PSD、epoch 图、位置；IC 地图、活动与投影 PSD |
| 连续数据 | 时间范围选择、拒绝/清除、采样坐标映射、EEGPrep 时间段删除及 boundary 事件 |
| 算法 | 振幅阈值候选、真实 ICLabel CPU 推断与概率选择、指定校准区间的连续 ASR 新阶段 |
| 桌面流程 | 四工作区、停靠与布局恢复、文件队列与正则搜索、评级备注、撤销重做、JSON 自动保存与 CSV |
| EpochLabel | 稳定匿名评分者、匿名分组、所见状态与算法暴露记录、显式同意的波形/标签包、上传回执及撤回 |
| 研究工具 | 特征 + 逻辑回归基线、按被试/研究/实验室留出、训练侧标准化、重复上传去重、JSON 推断候选 |

线性空间操作复用固定算子，ERP 复用输入累计和。ASR 是单独物化阶段，并限制缓存数量；不尝试把非线性清理强行变成线性 ERP 更新。来源 ICA 在 ASR 后失效；插值、参考或删通道后的导出也清理不再有效的 ICA 字段。

计算队列合并重复请求，结果同时检查数据、处理和视图版本，过期结果不得覆盖当前图。人工标记记录实际已经画出的滤波和处理状态；尚未画出的新处理状态或连续时间窗口不能被标记。网络操作使用另一条后台队列。

## 科学与状态验证

- **27 项 pytest 用例通过**：ICA 与 EEGPrep 对照、插值组合、条件/基线/增量 ERP、显示 FIR 的窗口及导出一致性、连续 ASR 与边界、会话恢复、来源映射、旧结果丢弃、实际绘制 ERP 与标记上下文、连续采样窗口切换、贡献标签/波形一致性、接收/撤回和模型分组。
- Ruff 检查及格式检查通过；ASR 上游处理文件保留原格式以便追踪差异。
- 公开 epoched 样例为 80 × 32 × 384、128 Hz、32 IC。排除 IC 1、插值通道 1、拒绝第 1 个 epoch 后，导出并回读 79 epochs，与同一预览内核一致。直接 EEGPrep 组合调用的最大绝对差约 **0.0000252 µV**，来自输入 float32 单位转换等舍入差异。
- 对应 MAT v7.3/HDF5 公开样例已单独读取对照；信号与 v5 + .fdt 样例最大绝对差为 **0 µV**。
- 公开样例已实际运行 EEGPrep ICLabel，输出 32 × 7 有限概率且每行和约为 1；概率表已在实际对话框中检查。这不代替独立分类效能评价。
- 连续 ASR 使用公开样例前 60 秒、0.5 Hz 高通、cutoff 20、0–20 秒校准，与独立去零行伪逆参考的最大绝对差约 **0.0000117 µV**；输出最大幅值约 **119.25 µV**。
- 上传/撤回通过本机接口与客户端验证，没有部署公共服务或上传用户研究数据。模型测试使用确定性构造的贡献数据；没有将其结果当作真实 EpochLabel 泛化指标。

ASR 验证发现 EEGPrep 0.4.0 默认 NumPy 伪逆在屏蔽子空间上保留浮点零空间，产生异常重建放大。本版本采用窄范围的 SciPy 伪逆兼容修正，保存实现版本并保留第三方许可。完整原因、计算参考和复现方式在 [ASR_NUMERICS.md](ASR_NUMERICS.md)。

公开样例固定于 [EEGPrep 示例目录](https://github.com/sccn/eegprep/tree/f22111a576f1beacbb1ed44069ef16c871f77765/sample_data)。报告在 output/reference/validation.json 与 asr-validation.json。测试仍会显示 EEGPrep 的 NumPy 弃用提示和 Starlette 测试客户端的弃用提示，未修改或屏蔽上游警告。

## 本机性能

2026-10-30 重新测量；Windows 10 / Intel Haswell，NumPy 和 SciPy BLAS 均为 2 线程。合成数据 500 Hz、每段 1.2 秒，预热后重复 30 次。以下是计算内核 p95，**不包含完整 GUI 绘制**。

| 项目 | 64 通道 × 300 epochs | 128 通道 × 400 epochs |
|---|---:|---:|
| 输入 float32 | 46.08 MB | 122.88 MB |
| 首次 ERP 准备，单次 | 579 ms | 627 ms |
| 5 epochs、32 可见通道变换窗口 | 2.25 ms | 4.19 ms |
| 删除/恢复 epoch 后 ERP | 0.47 ms | 1.06 ms |
| 切换排除 IC 后 ERP | 0.35 ms | 0.70 ms |
| 结束时进程常驻内存 | 200 MB | 373 MB |
| 峰值工作集，含合成信号构造和库加载 | 356 MB | 831 MB |

完整记录在 output/benchmark-v2-64.json 与 benchmark-v2-128.json。首次滤波或 ASR 包含整段计算，不使用暖缓存线性操作的毫秒数字描述。真实文件的端到端交互 p95 仍需专门验收。

## 界面检查与后续范围

四工作区及本轮新增对话框已实际渲染。output/ 中提供 eegqc-v2-combined-erp.png、eegqc-v2-condition-editor.png、eegqc-v2-iclabel.png、eegqc-v2-contribution.png 与 eegqc-v2-asr.png。最后一张使用公开连续文件，带已采用 ASR 与时间段标记。

下一轮主要工作是代表性 64–128 通道真实文件的完整 QC 流程验收、必要的事件/行为元数据兼容、可取消长计算、Windows 便携包和真实交互性能测量，随后交付重新拟合 ICA 及其保存恢复。ManualQC 输出可辅助比较，不要求逐项功能对齐。EpochLabel 还需要实际多人/多实验室采集、标签一致性审计、独立专家集和跨域评价；已有采集/训练工具不等于已有可靠的通用模型。

边界负责格式和必要计算前提检查；内部遵守数据契约。没有交互全量哈希、层层扫描、无效数据静默替换或以启动成功充当科学验证的测试。
