# EEGqc 下一阶段开发计划

日期：2026-10-30；起点：已发布到仓库的 0.2.0，提交 4710151。

目标：让研究者独立完成一份真实 EEG 数据的人工 QC，并得到与界面所见一致、可保存恢复的结果。

本计划替代旧方案中“完整对齐 ManualQC”的验收要求。ManualQC 只提供功能和交互参考；是否开发某项能力，由实际 QC 流程中的需要决定。既有技术背景保留在 [总体设计](../DEVELOPMENT_PLAN.md)，当前完成情况见 [实现与验证记录](IMPLEMENTATION_STATUS.md)。

## 一 交付范围与优先级

下一阶段分两次交付。A 先改善现有流程，可独立提供试用；B 在此基础上增加 ICA 重拟合。B 的开发不阻止 A 交付，也不把其功能提前标成已完成。

| 交付 | 建议版本 | 必须完成 | 不作为该次交付条件 |
|---|---|---|---|
| A 真实流程试用版 | 0.3.0 | 当前 QC 状态与视图一致、代表性数据验证、实际交互性能、长任务反馈和取消、Windows 便携包 | 新 ICA 算法、全部 ManualQC 功能、通用 EpochLabel 模型 |
| B ICA 增强版 | 0.3.1 | 从当前已采用状态拟合 ICA、新分解预览与 ICLabel、分解保存恢复、正确导出 | 多种 ICA 算法比较、自动参数搜索、任意流程编排 |

本轮继续使用 Python、EEGPrep、NumPy/SciPy、PySide6 和 PyQtGraph。保持 EEGPrep 0.4.0 与当前 ASR 兼容修正，具体缺陷需要升级时单独处理。Rust、前端重写和整体架构迁移不进入本轮。

以已有能力完成三个场景作为范围依据：

1. 分段数据已有 ICA：查看 IC → 排除并预览 → 采用 → 查看/插值坏道 → 标记 epochs → 比较条件 ERP → 保存、恢复及导出。
2. 分段数据没有 ICA：直接检查通道与 epochs，完成条件 ERP 和导出；B 交付后可以在已采用的数据上拟合 ICA。
3. 连续数据：查看波形 → 标记时间段 → 按需要预览 ASR → 采用 → 继续检查 → 导出保留数据及事件映射。

算法使用由用户决定，ASR、插值、重新 ICA 均不成为每份数据的强制步骤。

## 二 本轮不扩展的内容

- 不为满足 ManualQC 对照表补齐低频菜单、旧布局、输出选项或 RaterTool。
- 不增加通用 DAG 编辑器、分支树、事件溯源系统、数据库、插件市场或服务总线。
- 不增加云端账号体系、团队权限平台、公开数据托管、自动上传或自动更新。
- 不同时接入多种新 ICA、epoch 检测和插值算法；先让现有操作连贯可用。
- 不训练或发布未经独立验证的通用 EpochLabel；本轮只维护已有标签与处理状态的对应。
- 不以代码行数、测试数、覆盖率或算法数量作为交付指标。

出现新需求时，先说明它阻碍了哪个实际步骤。不能关联到本轮三个场景的需求进入后续列表；必要功能满足验收后停止扩展。

## 三 工作包 A1 明确处理状态与人工判断

**要解决的问题：** 用户应知道正在看什么数据、修改是否已采用、最终导出哪个结果。已有判断不能因切换处理方式而被错误地解释为新数据的标签。

**实现内容**

- 保留“输入、当前已采用、候选、固定参考”四种语义。工具栏或检查面板显示简短处理摘要；候选只有在“采用并继续 QC”后成为当前状态。
- 明确每个属性视图使用的信号：通道属性跟随当前/候选处理；IC 属性标明所属分解与拟合输入；ERP 标明条件、样本数、基线及对比方式。
- 保留现有撤销/重做。增加“恢复固定参考为当前”的明确操作时，恢复相应处理和决定，并允许一次撤销；不增加可视化历史树。
- 标记依据实际完成绘制的信号和显示设置。切换窗口或新处理尚未画出时，给出一次就地提示。
- 旧决定保留判断时的状态。处理变化后只汇总提示待复核数量，不自动变成当前状态的有效好/坏标签。
- 显示滤波继续属于观看设置，不隐式进入拟合或导出；处理算法自身包含的滤波明确写入其处理记录。

本轮不永久记录每次鼠标操作或所有撤销步骤。当前决定被重新复核时按既有规则更新；研究上需要保留处理前后标签时，可在相应状态显式导出已有贡献包。

**改动位置：** core/state.py、application/session.py、ui/main_window.py、ui/workflows.py；仅在数值数据基底或新 ICA 归属需要时补充字段。

**验收：** 同一 epoch 完成“输入标坏 → 去 IC → 采用 → 复核保留”，每一步所见信号、决定、参考和导出一致；撤销与恢复会话保持其正确归属。

**停止条件：** 四种状态和上述流程清楚可用，不继续开发任意状态分叉、合并或流程编辑器。

## 四 工作包 A2 真实数据兼容与交互性能

### 数据范围

先使用少量能覆盖差异的文件，不建立大型样例仓库。

| 数据 | 用途 |
|---|---|
| 已有公开 EEGPrep 分段样例及对应 HDF5 | 保留数值、读取与导出对照 |
| 一份常用 64 通道分段数据 | 实际事件、行为/条件字段、已有 ICA 与日常 QC |
| 一份常用 128 通道、几百 epochs 的数据 | 交互延迟、内存及降秩等实际情况 |
| 一份已有 boundary 或时间段删除需求的连续数据 | 连续标记、事件坐标、ASR 前后比较 |

文件可以同时覆盖多个场景。实际文件尚未提供时，使用现有公开样例和明确标记的合成数据推进；交付记录单独列出仍待实际文件验证的部分，不把合成数据结果写成真实研究验收。

对每类数据只记录必要背景：通道、采样率、epoch 数/时长、单位、事件字段、ICA 来源和已知处理。研究数据不提交到源码仓库。

### 兼容修复

优先处理会造成错误结果或阻止主要流程的问题：事件错位、条件值解析、通道顺序、ICA 归属、单位和导出回读。针对实际遇到的结构补充适配；不提前支持所有 MATLAB 嵌套形式和所有 EEG 文件格式。

缺少位置时，保留可用的波形和标记功能，并说明插值/地形图缺少位置。已有布局错误或损坏的分解在导入边界报告具体问题，不能填零继续计算。

### 性能目标

当前 128 通道 × 400 epochs 合成基准中，单个 epoch 删除/恢复后的 ERP 内核 p95 约 1.06 ms；这一数字不包含界面绘制。新测量从操作触发开始，到包含新数据的 Qt 绘制完成为止，并说明不包含操作系统显示合成延迟。

初始目标适用于已经载入、暖缓存、16–32 个可见通道，显示少量 epochs 或约 10 秒连续数据：

| 操作 | 初始目标 p95 |
|---|---:|
| 翻页或切换当前 epoch | ≤100 ms |
| 切换 IC 后波形与可见 ERP 更新 | ≤150 ms |
| 已建立插值权重后的预览切换 | ≤200 ms |
| 拒绝/恢复 epoch 后可见 ERP 更新 | ≤100 ms |

首次读盘、首次滤波、首次插值准备和 ASR/ICA 总耗时另记，不混入暖缓存交互指标。先在真实使用机器测量，再按实际数据规模调整目标，并记录调整原因。

扩展现有 benchmarks/，使用固定操作序列、一次预热和约 30 次采样，输出 p50/p95、数据形状、运行环境与进程内存。每个性能改动运行相关场景；不把全部性能测量加入每次提交的自动检查。

优化顺序是可见窗口的数据量、绘图对象复用、重复属性计算和不必要的数组复制。只有测到某一步阻塞，才增加对应缓存或调整线程。先保留现有有界缓存，避免多级缓存、自动预计算和后台全量扫描。

**改动位置：** adapters/eeglab.py、core/preview.py、ui/waveform.py、相关属性视图、benchmarks/。

**验收：** 记录每个主要操作的端到端延迟，并修复实际可感知的阻塞；连续检查和重复切换不会使内存随操作次数持续增长。导出回读的信号、事件和来源映射符合当前工作状态。

**停止条件：** 达到本轮数据范围的体验目标后停止优化，不为了更低的内核数字引入新语言或计算框架。

## 五 工作包 A3 长任务反馈与取消

**要解决的问题：** 当前数值队列串行执行，长算法可能占住预览任务；丢弃过期结果也不等于真正取消计算。

**最小实现**

- 保留现有预览队列及重复请求合并。ICA/ASR 等长算法采用一个专用子进程执行，同一时刻只运行一个重计算任务。
- 应用层保存一个任务记录，包含任务 ID、数据及输入处理状态、参数、执行状态和结果。只提供启动、进度、取消、成功、失败这些实际需要的动作。
- 后端有迭代回调时展示真实进度；没有回调时显示当前阶段和已用时间，不编造百分比。
- 有自然检查点的任务协作取消；无法中断的第三方计算在独立子进程中取消和回收。不得强行终止正在操作 Qt 或会话对象的线程。
- 子进程只产出结果或临时产物，由主进程接收成功结果后生成候选。取消或失败不会提交半个处理状态。
- 任务输入在启动时固定。浏览、缩放、备注等无关修改不使计算作废；上游处理或拟合选择发生变化时，结果显示其原始输入，不能自动覆盖新工作状态。
- 等待长任务时仍可查看已载入数据；切换数据集后旧结果不得应用到新数据集。
- 导出成功后才显示完成。取消时清理该任务自己的临时输出，已有输出不被半成品覆盖。

先测量一次输入传递的开销。只有大数组复制成为内存或延迟问题时，才使用任务临时 .npy/memmap；不先建设共享内存管理器。保留现有网络队列，不统一成通用调度平台。

**改动位置：** application/ 中一个小型长任务模块、现有 ui/jobs.py 的调用边界、ui/workflows.py。数值函数保持无 Qt 依赖。

**验收：** 在执行 ASR 时仍可浏览，取消后已有处理和标签不变；后续任务能够正常执行。晚到的成功结果不能恢复已取消任务或修改另一份数据。Windows 打包环境中的子进程行为需要同样通过。

**停止条件：** 单个长任务可反馈、可取消、结果可采用即可；不增加任务优先级系统、自动重试、断点续跑和分布式执行。

## 六 工作包 A4 界面整理与 Windows 试用交付

### 界面

沿用四个工作区，不重新设计整套皮肤。优先修复实际流程中的选择、反馈和上下文：

- 切换工作区后保留 epoch、通道、时间窗口和幅度。
- 点击通道或 IC 后，其属性更新到对应对象；较慢的属性计算不会挡住波形浏览。
- 候选、已拒绝、已确认保留和未检查有可辨别的显示；多选操作明确显示数量。
- 连续数据使用时间段措辞与导航，不显示无意义的 epoch 操作。
- 批量标记、确认保留、取消、撤销和下一项通过现有控件及快捷键完成。
- 更新中保留旧曲线并标明其状态；错误在操作位置说明一次，避免连续弹窗。
- 高级算法参数按需展开；以普通显示器和系统缩放下能完成主要操作为验收。

不新增主题市场、自由搭建所有视图、可配置快捷键编辑器或通用属性面板系统。

### 发行

先制作 Windows x64 便携目录包，解压后可启动；无需用户自行安装 Python。先锁定一个现成打包工具并验证 Python/Qt 与数值库的兼容，再完善打包脚本，不同时维护多种发行方案。

包内提供桌面 QC 和明确的合成演示入口。ICLabel 的 PyTorch 与模型资源需要在打包验证中实际测试；若体积或兼容性阻碍首次交付，首包明确标为基础 QC 包，后续在同一打包配置中补齐 ICLabel，不长期维护两套发行方案。通过 Python 项目运行的 ICLabel 继续可用。贡献服务器和训练命令继续通过 Python 项目提供，不放入首个桌面包。

在一台没有项目开发环境的 Windows 机器或干净虚拟机中，完整执行“打开真实 .set → 修改 → 保存 → 关闭重开恢复 → 导出回读”，并检查中文/空格路径、模型资源和长任务取消。这是一次发行工作流验收，不是只检查窗口能打开。

**交付物：** 可复现的打包配置、便携 zip、简短使用说明和已知限制。

**停止条件：** 可独立完成工作流后交付；自动更新、代码签名、系统安装向导和多平台发布随后按实际需要安排。

## 七 工作包 B1 从当前状态重新拟合 ICA

**功能边界：** 本轮先支持一种 ICA 方法。以已安装 EEGPrep 0.4.0 的无 GUI pop_runica 路径和 Extended Infomax 为首选，先做小型能力验证，再锁定具体参数接口；不同时加入 AMICA、多个替代后端或自动算法选择。

### 拟合输入与参数

- 默认输入为当前已采用的科学处理状态，显示滤波不参与拟合。
- 默认使用保留的 EEG 通道；允许用户调整拟合通道。记录实际通道 ID、顺序、数据状态和样本选择。
- 默认使用当前未拒绝的 epochs，或连续数据未标记删除的时间段；允许显式改为全部样本。启动前展示范围和数量。
- 分段数据在拟合边界按后端要求整理为样本矩阵，原 epoch/event 坐标仍由数据集保留。这不授权将 epochs 拼接后运行依赖连续性的滤波或 ASR。
- 只提供必要参数：拟合通道、样本范围、成分数/秩以及最大迭代数等少量高级选项。随机种子在后端支持时记录。
- 拟合前针对选定输入计算一次有效秩。平均参考、插值或此前去 IC 造成降秩时，成分数受有效秩约束，并在参数摘要中可见。更低的 PCA 维度由用户明确选择。
- 不在拟合期间默默改参考、去坏道或增加滤波。需要不同前处理时，由用户先采用对应状态。

### 新分解的归属

原始 Dataset 与来源身份保持稳定。每个新分解具有普通 ID，绑定产生它的输入处理、拟合通道/样本和后端参数。IC 编号仅在该分解内有效。

复用现有 Processing、Session 和预览引擎，在它们确实需要的地方加入分解/基底引用。只有新 ICA 或 ASR 等改变计算基底的操作才形成新的阶段对象；每次 IC 勾选、epoch 标记或缩放不会复制整个数据集。

新分解首先作为候选显示。用户采用后，IC 地图、时序、选择和 ICLabel 均指向新分解；旧分解的 IC 勾选或概率不会继承为新分解的标签。拟合本身不意味着已删除任何成分。

对于后端的中心化、白化、秩和重建约定，在适配器内明确处理。无成分排除时保持原科学输入；发生排除后的重建遵循选定 EEGPrep 语义。不能为了让矩阵形状相符而额外中心化或补零。

**改动位置：** adapters/ 中 ICA 薄适配器、core/dataset.py/state.py/preview.py、application/session.py、IC 工作区和算法对话框。已有 ICA 导入路径保持其已有语义。

**验收：** “ASR 或其他已采用处理 → 拟合 ICA → 查看新 IC → 排除一个 IC → 采用 → 标记 epochs/时间段”走通；参考状态仍可查看原输入或之前已固定的状态。

**停止条件：** 一种方法完成拟合、预览、采用和取消即可。性能或质量问题需要另一算法时，单独给出测量依据和后续任务。

## 八 工作包 B2 新分解保存恢复与导出

ICA 重拟合只有在关闭应用后能够恢复，并能正确导出时才算完成。

- 会话 JSON 保存分解 ID、输入处理、拟合选择、参数、版本及数组文件引用。
- 新生成的 mixing/unmixing、必要的中心化/白化信息等写入普通 .npz 或 .npy，禁用 pickle。优先保存恢复所需的小型矩阵，不为每次 ICA 拟合复制整份 EEG 信号。
- 恢复会话直接加载已保存的分解，不用“重新跑一次同参数 ICA”代替恢复。记录随机种子不能替代保存矩阵。
- 保存当前、固定参考和现有决定所引用的分解与必要输入阶段；不持久化全部临时预览和完整撤销历史。
- 保存采用“先完成新数组文件，再替换引用它们的会话 JSON”的顺序；失败时保留上一份有效会话。只清理明确属于当前任务的未完成文件，不引入全局扫描和自动垃圾回收服务。
- schema 增加版本，只实现现有 v1 到新格式的一条显式迁移；打开旧会话不自动覆盖原文件。
- 导出继续调用同一科学内核；实际导出信号、通道/参考和 ICA 相容时写入对应分解，否则清除失效字段并保留处理说明。
- 来源 epoch、通道与连续采样映射独立于内部数组压缩，删除后事件不漂移。
- EpochLabel 贡献包仍重建“当时判断的状态”。新 ICA 仅要求补足分解归属，不扩展采集平台或自动继承旧质量标签。

**改动位置：** application/persistence.py、adapters/eeglab.py、epochlabel/bundle.py；需要时更新 .gitignore 以排除运行时数组文件。

**验收：** 新 ICA 结果采用并标记后保存，重启恢复，再导出回读；同一状态下预览、恢复结果和导出数值一致，IC 分解和标签不会错配。

**停止条件：** 正常保存、明确失败和旧会话导入可用即可；不增加通用迁移框架、内容寻址存储或远程同步协议。

## 九 验证纪律与编码边界

验证集中在会影响科学结论、状态归属和用户工作保存的地方。沿用已有 27 项测试；本轮新增测试由具体风险驱动，不设新增数量目标。

| 风险 | 需要的验证 |
|---|---|
| 新分解归属错误 | 来源 ICA、新 ICA 和固定参考切换后，IC 图、排除结果及标签引用正确 |
| ICA 数值约定错误 | 小型已知混合信号与 EEGPrep 对照，覆盖实际涉及的降秩、通道选择和中心化；允许 ICA 的符号/排列不唯一，以重建信号等不变量比较 |
| 保存恢复丢失计算依据 | 新分解保存、重启恢复、导出回读结果一致；旧 v1 会话能导入 |
| 取消后误提交或旧结果覆盖 | 一个受控慢任务验证取消、换数据和晚到结果，配合真实长算法流程检查 |
| 实际元数据错误 | 针对出现过的事件或条件解析缺陷保留最小回归案例 |
| 打包缺少依赖/资源 | 干净 Windows 上完成真实工作流，而非仅启动窗口 |

测试执行方式：

- 日常只运行改动涉及的数值、状态或界面测试；合并一个完整工作包时运行相关全套检查。
- 稳定后可加入一个 Windows/Python 版本的简单 CI：Ruff + pytest。模型下载、性能基准和大数据验证不加入每次 PR。
- 多个按钮共享同一操作逻辑时，测试该操作的实际结果，不为每个按钮重复写 smoke test。
- UI 布局、文字和颜色改动以实际查看为主，不增加截图像素基线系统。
- 依赖或代码未变化且没有新疑点时，不重复运行已经通过的检查。
- 数值测试使用有依据的单位和容差，不因参考实现也产生异常就认为两者一致。

边界规则：

| 位置 | 必要检查 |
|---|---|
| 文件导入 | shape、单位约定、事件/通道对应及所需 ICA 字段 |
| 算法启动 | 当前状态、选定样本、通道、秩等实际前提 |
| 会话恢复 | 格式版本、来源路径/大小/修改时间和布局；新数组的存在、类型与形状 |
| 外部贡献入口 | 保留已有授权、格式及体积限制 |
| 内部计算 | 遵守已建立的数据契约，不在每层重复遍历和校验完整数组 |

普通状态使用 UUID、递增 revision 和实际依赖字段。**本轮不新增全量数据哈希、分块哈希或点击时校验。** 路径、大小和修改时间用于发现来源变化，不被宣称为内容一致性保证。

不使用大范围异常捕获后返回空数据、零矩阵或换算法；应用边界报告一次具体错误并保留已有工作。正常错误处理只覆盖会发生的输入、算法及写入失败，不为假设场景建立重试与恢复平台。

## 十 开发顺序与工作量

估算为一位熟悉当前代码和 EEG 的开发者的专注工作日，包含针对性验证，不包含等待真实数据、外部试用反馈或新的上游数值缺陷。按任务完成度推进，不承诺固定日历日期。

| 顺序 | 工作包 | 预计 | 主要产物 |
|---|---|---:|---|
| 1 | A1 状态与判断语义 | 2–3 天 | 清楚的当前/候选/参考显示和正确的标记归属 |
| 2 | A2 真实数据与性能 | 2–3 天 | 必要兼容修复、代表性延迟和内存记录 |
| 3 | A3 长任务反馈与取消 | 2–3 天 | 一个可取消的重计算执行路径，ASR 先接入 |
| 4 | A4 界面与 Windows 便携包 | 2–3 天 | 0.3.0 试用包和使用说明 |
| 5 | B1 ICA 重拟合 | 4–6 天 | 一种 ICA 方法的新分解预览与采用 |
| 6 | B2 分解持久化与导出 | 2–3 天 | 0.3.1 完整 ICA 工作流 |

合计约 14–21 个工作日，按实际反馈调整。A2 的文件准备可与 A1 并行；B1 对 EEGPrep 接口的小型验证可提前，但完整接入依赖 A1/A3。B1 与 B2 合并验收，避免发布只能在当前进程使用的新分解。

每个工作包使用一个范围清晰的分支/PR，描述实际问题、最终行为和相关验证。为了排版拆文件或未来可能复用而进行的重构不单独立项；只拆分本次修改已经造成理解困难的职责。

如果时间不足，优先交付 A；B 延后。若某个工作包超过估算且主要成本来自低频扩展，先收窄扩展，保持主流程完整。

## 十一 版本完成条件
